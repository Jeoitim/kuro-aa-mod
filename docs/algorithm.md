# 架构

游戏完成场景绘制后，KuroUI 在已确认的界面边界调用 ReShade；AeonSR 获取颜色和可用深度，估算运动信息，再执行厂商的原生分辨率抗锯齿。结果写回场景，游戏继续绘制界面。

## 场景与界面

引擎边界规则通过 PE 时间戳、映像大小和函数代码指纹确认 UI 提交入口，再用调用栈识别它。有效场景目标必须符合尺寸和颜色格式要求。UI 早于场景、入口校验失败或目标未确认时跳过处理，不自动改成全屏 AA。

主场景每帧只处理一次。首次 UI 位于小型辅助目标时，可先处理已完成的主场景，再恢复辅助目标继续绘制。ReShade 负责保存、恢复游戏绘制状态，缓存的 RTV 引用在帧末或命令列表销毁时释放。

角色实验路径识别独立几何纹理，并通过 `AeonSRProcessPreview` 显式处理。每个视图使用独立历史和厂商上下文，不借用主场景深度，不启用投影抖动。处理后恢复原始透明度和 DX11 状态。

## 原生 AA

正式版固定使用 NVIDIA DLAA、AMD FSR Native AA 或 Intel XeSS Native AA。管理器、配置读取、主场景参数和角色接口均限制为原生模式，旧配置不会重新开启其它档位。

默认高运动估计、锐化 0；`SpatialJitter`、`KeepInterface` 和 `NeuralRender` 均关闭。首次运行按实际渲染 GPU 选择后端，也可在管理器中手动指定。

AeonSR 负责 DX11 / DX12 桥接、光流和厂商运行库调用。光流是估算结果，缺少游戏原生运动矢量、可靠相机矩阵及完整遮挡信息，仍可能在头发、透明特效、重复纹理或快速转动时产生残影。

## 回调与构建

ReShade 没有 technique 时会提前返回，因此 `Runtime.fx` 注册一个默认禁用的占位 technique。它只保证回调可用，不进行图像处理。

上游源码固定于 `8e8456848557d6e7282db3451473531a392209da`，本项目分别保存角色扩展、缓存预热及原生模式限定的补丁。降倍率实验保存在独立分支，正式版不包含相关钩子。
