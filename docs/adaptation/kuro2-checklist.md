# 云豹版《黎之轨迹 II》适配清单

目标是让二代使用现有 DLAA / Native AA，并正确分开场景、文字和独立角色视图。保持原生尺寸，不恢复倍率实验。下次运行前先准备好采集组件，尽量用一次启动收齐资料，再完成实现和验证；未知入口和特殊页面仍可能需要补充采样，不能保证一次运行覆盖全部问题。

## 当前基线

正式版为 0.4.1，原生 AA、角色接口、缓存和预热已通过独立夹具；二代的游戏边界、shader 签名和安装识别尚未验证。一代配置目前硬编码在 `src/Settings.cs`、`packaging/profiles/KuroCLE.ini` 和 `src/KuroUI.cpp`，不能直接复制到二代。

以下仅作一代对照，不是二代候选值：

| 一代已确认资料 | 值与口径 |
| --- | --- |
| 云豹版本 | 1.1.0，DX11 |
| PE 时间戳／SizeOfImage | 1730414432／9019392 |
| UI 批提交入口 RVA | `0x37F480` |
| 入口前 32 字节 FNV64 | `533ebf8ba7423d58` |
| UI PS／VS 哈希 | `23f7ff8def7a9871`／`323e5c4e7ef5ce9` |
| Shader 哈希口径 | 对完整字节码使用现有 `shader_hash`，不能与函数前缀指纹混用 |

## 下次启动前

1. 核对 Git 状态、当前分支和已安装 DLL，先读架构、角色调查及验证记录，保留未提交修改。
2. 一次确认二代的发行商、版本、安装目录、实际 EXE 名、启动方式、输出分辨率和可用存档。当前没有已验证的二代程序名，不猜测。
3. 确认实际图形 API；仅在 DX11 立即上下文路径成立后复用现有采集。若 API 不同，先报告缺失能力。
4. 备份旧注入文件、Mod 设置与组件。给二代单独配置，不覆盖一代配置或厂商运行库。
5. 在单独适配分支准备有界采集、阶段标记和结果归档。首次只观察，边界未验证时跳过 AA，不能自动退回全屏处理。
6. 检查版本校验、采集上限、异常恢复和关闭诊断后的开销。必须更换 DLL 时才要求退出；在启动前一次完成组件准备。

## 一次运行需要收集的资料

| 资料 | 必须记录 | 用途 |
| --- | --- | --- |
| 程序与模块 | EXE 名、SHA256、PE 时间戳、SizeOfImage、发行商／游戏版本／Steam build（可取得时）、API、ReShade／Mod 版本 | 建立版本白名单，区分同名版本 |
| 主场景目标 | 颜色／深度的资源 ID、格式、宽高、采样数、层数、mip、视口、绑定阶段 | 找到已经完成的主场景，避免处理阴影或页面背景 |
| UI 边界 | 第一批文字／HUD／面板前后的帧号、draw 序号、调用栈 RVA；候选函数的起止 RVA、前 32 字节指纹及可确认的调用关系 | 验证处理位置确实在 UI 之前 |
| Shader 签名 | VS＋PS 配对哈希、阶段、目标尺寸／格式、深度状态、出现页面、首次／末次 draw | 建立备用签名规则，检查它是否也用于场景几何 |
| UI 资源流 | 输出 RTV／DSV、PS 输入资源与槽位、相同资源跨 pass 的关联、多目标绑定数量与实际尺寸 | 区分主场景、文字、离屏页面和合成目标 |
| 独立角色视图 | 模型颜色纹理及原始 alpha、尺寸／格式、几何提交调用栈、第一次被 UI 采样的位置、对应输入槽 | 在模型混入文字前执行独立 AA |
| 视图生命周期 | 创建／销毁、资源地址复用、换角色／尺寸变化、帧间断、切镜、分辨率切换 | 保证缓存和时域历史不会串视图 |
| 成本与回退 | 各阶段 CPU／GPU 时间、AA 次数、缓存创建／命中／退还、跳过原因与错误 | 避免重复处理，区分准备开销与持续帧时间 |

运行时地址只用于本次资源关联。可复用的程序位置记录成相对模块的 RVA，不能将 ASLR 后的绝对地址写进配置。函数指纹、版本字段与目标条件必须一起验证。

优先收集资源描述、调用栈和哈希，不回读整帧像素或 GPU 常量。必要时只保存有限的候选画面用于正确性对照，单独标记有同步开销，不能据此测正式性能。

## 采样顺序

预先准备带阶段标签的采集清单。一次启动依次经过标题／菜单、正常探索与 HUD、对话／立绘、装备／换装及角色切换、战斗 HUD／特效、暂停／地图或其它已知特殊页面。每阶段保留原生对照和边界证据，用户只需按一张清单操作，不反复加载同一存档、截图或切相同界面。

有可达场景时再检查 UI 先于场景、仅 UI 页面、辅助 UI 目标、场景与输出不同尺寸以及正常输出分辨率切换。没有覆盖的页面明确列为缺口，不能假称全部兼容。已开启 AA 后的稳定帧率检查与诊断采样分开。

## 现有诊断能力与盲区

`TraceDraws=1`、`TraceEngineCallers=1`、`TraceResources=1` 可记录 VS／PS 哈希、目标信息、游戏调用栈和像素输入。调用栈每 120 帧抽样一次，输入目前只检查前八个 PS 槽；不能据此断定其它槽为空。`CaptureCandidates` 涉及像素回读，默认关闭。

当前 `KuroUI-draws.csv` 每 300 帧写出时会覆盖旧文件，并清空聚合记录。下一 agent 必须先实现阶段归档／唯一文件名或有界追加，再开始长采样；否则最后一个 CSV 无法代表整次运行。采样文件应包含阶段、帧号、相对时间和采集口径。

现有规则只缓存第一个输出目标，资源追踪也不等同完整 MRT／SRV 绑定证据。需要验证多目标或其它槽时，先补齐有界的实际绑定记录。`TraceRenderLayouts`／`TraceRenderValues` 只在必要时使用：前者可能产生本地 shader 文本，后者有 GPU 回读成本，不能作为无开销性能采样。

首次二代采集必须清除一代的函数入口、指纹和 VS／PS 签名，设置 `SkipUnmatchedFrames=1`；在独立诊断配置中启用追踪即可。不要先把未知函数写进正式白名单或启用通用投影抖动。

## 从证据到实现

- 对照不同页面确认 UI 边界前有完成的场景，文字尚未混入；排除通用函数和偶然同尺寸目标。
- 优先按版本验证统一引擎入口；备用签名必须验证 VS／PS 配对及资源条件，不堆叠未经验证的哈希。
- 建立二代独立 profile，并将设置器、安装／升级／卸载的游戏识别从一代硬编码中分离。程序名、配置和 UI 规则按实际选定版本应用。
- 保持每帧一次主场景 AA；独立角色使用单独历史，保留 alpha、状态恢复、缓存预算与安全回退。
- 指纹失配、未知 UI 或不支持的资源保持原画面；全屏 AA 只由用户明确选择。
- 优化 PR 先给分段证据，再减少初始化、资源分配或检查。不同采样时段和重叠队列区间不能直接相减或相加。

## 交付与验收

资料包包含版本摘要、带阶段的 draw／资源流 CSV、候选函数表、VS／PS 配对表、已覆盖页面表、分段时间和已知缺口。配置里只保留已验证条目；报告区分静态定位、夹具通过与游戏通过。

完成检查：主场景可处理、文字保持隔离、角色 alpha 不变、无重复 AA、不同视图历史不混用、切角色／尺寸与资源销毁正确、错误指纹回退、仅 UI 与辅助 UI 页面安全，以及安装／卸载不修改游戏 EXE 或存档。保留测试源码，关闭并还原诊断配置，清理中间产物。

公开 PR 可包含代码、哈希／RVA 元数据、脱敏摘要和自有夹具；不要提交游戏 EXE、原始 shader、游戏反汇编、存档、私人路径或含这些资料的诊断包。底层帧追踪保留本机，用摘要支持结论。
