# AA 触发规则说明

管理面板提供三种互斥规则，默认“引擎边界”。保存后重新启动游戏生效，切换后端不改变规则。

| 管理面板 | KuroUI.ini | 处理位置 |
| --- | --- | --- |
| 引擎边界（推荐） | AARule=engine | 经校验的引擎 UI 提交前 |
| Shader 签名（0.3.1） | AARule=shader | 匹配的 UI shader draw 前 |
| 无规则（全屏 AA） | AARule=full | Present 最终画面，包含 UI |

显式 AARule 决定实际路径，切换时清除另一规则的入口参数，避免混用。
未带 AARule 的旧配置仍可读取，以便开发夹具和既有安装迁移。

## 0.3.1：Shader 签名

`EarlyUIShaderHash` 和 `EarlyUIVertexShaderHash` 是 shader 字节码的指纹，
不是“不做 AA 的 shader 白名单”，也不是文字区域坐标。

匹配双签名、目标尺寸 / 格式、无有效深度测试等条件后，Mod 在该次 UI draw **之前**
对已完成的场景颜色调用 AA。随后游戏继续执行这个 UI shader，文字和面板才被画上去。
因此“命中签名”是提前执行场景 AA 的触发点，不是关闭该 shader 的 AA 开关。

这是 0.3.1 文字改善的原因。限制是某些 UI 可能早于该触发点出现，
同一 shader 也可能用于小型 UI 目标；其它界面未必使用同一组合。

## 新版：引擎 UI 边界

新版识别经校验的游戏 UI 批提交函数上下文。PE 构建信息和函数代码指纹用于确认地址适用，
不是 shader 白名单。它结合已观察的 3D 颜色目标来确认场景与 UI 的时序。

首批 UI 提交前，处理当前主场景目标或缓存的已完成场景目标；
UI 首批位于辅助纹理时，也可先处理缓存场景。UI 开始后封闭本帧 AA，
入口或场景未确认则保留原画面，不分析最终文字像素，不做矩形回填。

这是更结构化的边界规则，但并非自动理解所有 C++ 类型或全部 UI / 3D 视图。
本游戏当前入口仍是特定构建的逆向结果，需要维护版本校验和代表性验收。

## 全屏基础路径

不使用场景 / UI 分界时，AeonSR 在 Present 的正常 ReShade 回调中处理最终画面。
场景与 UI 一起进入光流、重建和锐化，文字可能变软、变形或残影。
它不是“关闭抗锯齿”，也不能保证装备页的 3D 模型得到与原生集成相同的效果。

## 装备 / 换装 3D 展示

文字清晰与 3D 展示 AA 覆盖是不同问题。实际装备页采样确认模型先绘制到独立纹理，
随后作为 UI 输入合成；首批 UI 比这次合成更早，主场景 AA 因此可能漏掉模型。

验证版增加默认关闭的“角色界面抗锯齿（实验）”，通过资源关联在合成前处理模型纹理。
定制 AeonSR 为预览保存独立光流及厂商历史，绕过主场景每帧一次回调限制。
引擎边界和 Shader 签名两种规则均可启用，预览不借用主场景的深度或投影抖动。
完整覆盖、真实画质和性能仍需游戏验收，详见 [厂商预览](vendor-preview.md)。
关闭规则可用于 A/B 判断最终画面处理是否能改善预览，但会失去 UI 保护，不作为默认建议。
