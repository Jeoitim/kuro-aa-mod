# 场景着色降载实验

这是尚未在游戏中完成性能与画质验证的开发实验，默认关闭，不属于已发布 0.4.0 的功能。

## 与 DLSS 档位的区别

当前 DLSS / FSR / XeSS 档位没有降低游戏原本的场景渲染分辨率。VRS 则通过 NVIDIA 驱动接口减少部分场景的像素着色调用，保持颜色、深度目标和 UI 尺寸不变。
它不等于低分辨率渲染，也不会减少模型顶点、阴影或全部后处理成本。CPU 受限时可能没有帧率收益，细节也可能变差。

## 实验范围

`KuroUI.ini` 的 `[KuroUI]` 段可设置 `SceneVRS`：

| 值 | 含义 |
| --- | --- |
| 0 | 关闭，默认值 |
| 1 | 2x1 像素共享一次着色 |
| 2 | 2x2 像素共享一次着色，画质损失可能更明显 |

需要支持 NVIDIA DX11 VRS 的显卡与驱动，不因选用 FSR / XeSS 就获得 AMD / Intel 硬件支持。不支持时保持原绘制。

当前仅处理即时上下文中、深度测试开启、单采样、至少 1280x720 的 RGBA16F 颜色目标，且必须位于本帧已识别的 UI 边界之前。
不符合条件的绘制、帧结束和运行时退出时关闭降载。独立角色视图不在这一实验范围内。
这种限制仍不能证明所有游戏绘制都属于场景；实际菜单、透明物体与剧情 UI 必须验证，不能宣称已完全隔离。

## 已完成的检查

作者的 RTX 3060 Laptop 上，独立 DX11 夹具的五次全屏绘制共调用 10,368,000 次像素着色；两种模式分别为 5,184,000 和 2,592,000 次，关闭后恢复为 10,368,000 次。
通过 ReShade / KuroUI 实际注入后也得到相同调用数，随后关闭深度测试的 UI 绘制在每种模式下均保持完整调用数。

重负载测试 shader 的一次独立测量约为 0.454 / 0.229 / 0.115 毫秒每次绘制。重复测试中各模式均出现过显著时间波动，包括注入基线约 4.43 毫秒的异常样本，因此不把这些时间当作稳定收益，更不能换算成游戏帧率。
尚需在同一游戏场景、固定帧率限制与画质设置下重复比较 GPU 帧时间、平均帧率及低帧，并检查文字、头发与透明材质。

接口与类型来自 [NVIDIA 官方 NVAPI SDK](https://github.com/NVIDIA/nvapi)，通过系统驱动动态加载；不分发驱动 DLL。参考 [DX11 接口文档](https://docs.nvidia.com/nvapi/group__dx.html)。
