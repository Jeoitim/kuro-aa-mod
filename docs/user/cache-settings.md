# 缓存与启动预热

0.4.1 包含这些缓存和预热设置。角色界面抗锯齿仍是实验功能，默认关闭。

## 预算和数量

缓存预算滑条为 128–4096 MB，步长 128 MB，默认 512 MB；数量上限可选 4、8、12、16，默认 4。
预算是按像素与每个上下文的固定开销估算，不是厂商内部显存的精确字节数。

新增缓存必须同时满足数量和预算条件。任一超限都会执行“缓存满后”策略。
开启“按可用显存限制”时，还会查询游戏所用 GPU 的本地显存预算，保留至少 256 MiB 余量，并只使用剩余余量的一半作为新增缓存空间。
驱动不支持查询时退回手动预算。自动保护不在每帧强制销毁已有缓存，也不能保证完全避免其它游戏资源造成的显存压力。

高分辨率或模型尺寸较多时可先尝试 1024 MB、8 个上下文，再比较显存占用和卡顿。
预算调高不代表立刻分配全部容量，也不会绕过可用显存保护。
不支持 0＝无限制，输入 0 会被设置器拒绝；直接修改配置的异常值会被限制到有效范围。

## 缓存满后

- 跳过 AA：默认选项。额外模型保持原画面，不淘汰已有缓存，优先减少停顿。
- 排队准备：记录请求，在帧结束回收一个已退还或至少两帧未使用的闲置上下文。后续再遇到该目标时准备资源并恢复 AA。请求队列最多八种尺寸，过期请求会丢弃。

排队准备不是完全异步的 GPU 初始化，回收和后续创建仍可能卡顿。不能回收正在使用的上下文，也不绕过手动预算或显存余量限制。只提高预算并不能让一个超过单实例预算的模型进入队列。

## 编译缓存与预热

“保存编译缓存”将光流和透明度保护着色器的编译结果保存到用户本地的 `KuroAA/shader-cache-v1` 目录，并在同一进程内复用。
缓存键包含源码、入口、编译参数、宏定义及编译器文件信息；读取时检查校验和与 DXBC 有效性。损坏缓存会按需重新编译。

“启动时后台预热”以较低线程优先级提前准备两种光流质量的基础着色器。关闭编译缓存时不执行预热。
它不恢复上次运行的画面历史，也不提前创建全部厂商实例或保证加载完全无停顿。GPU 管线和纹理仍需在设备有效后创建。

单元检查确认第一次编译、第二次进程磁盘命中及损坏缓存回退。一次夹具运行的光流预热完成时间为 1.359 秒；另一进程命中 20 项磁盘缓存，未重新编译，完成时间为 0.099 秒。
这些是编译预热结果，不是游戏整体加载耗时或帧率提升。
