# 对话模型缓存优化

用户在剧情与战斗对话中观察到独立 3D 模型会反复触发卡顿，并非只发生在游戏首次加载。
一次运行日志里，512x512 厂商特征创建四次，1024x1024 创建两次，1920x1080 创建三次。
其中有重复的 Preview 初始化，说明已有的双上下文池仍会淘汰不同尺寸的模型。

本轮修改采用按尺寸保留的缓存，不改变主场景 AA 规则：

- 厂商上下文最多四个，总输出像素预算为四张 1080p 纹理。
- 纹理销毁后保留上下文；同尺寸模型复用它，重新积累各自的时域历史。
- 同一资源地址换了尺寸时，保留原尺寸上下文，不原地销毁重建。
- 池满时额外模型保持原画面，不同步淘汰已准备好的上下文。
- 透明度保护纹理也按尺寸缓存，避免每次交替都分配和释放。

这是减少重复初始化的优化，不是完全异步的后台预热。首次出现新尺寸仍可能停顿，
正常光流和厂商重建仍会增加 GPU 帧时间，缓存还会增加常驻显存。实验功能继续默认关闭。

混合尺寸夹具保留固定主场景，再反复显示三种尺寸的模型。
缓存饱和夹具显示六种尺寸，检查只创建四个上下文，后续未缓存模型与原画面一致。
用户试用后确认，重复初始化基本不再出现。这是实际体验反馈，不能用夹具结果替代游戏帧时间，也不能保证首次出现新尺寸完全无停顿。

## 本轮验证

三后端、两种规则的六组 840 帧尺寸交替测试全部通过：各创建三个预览上下文，
返回已有尺寸的四次切换均复用缓存，UI 与原始 alpha 不同像素为 0。
DLAA 两种规则的 720 帧缓存饱和测试各只创建四个上下文；末尾未缓存模型的 RGB、UI 与 alpha 均和基线相同。
安装卸载与默认关闭检查通过。本机已安装试用组件，配置保持原样；优化尚未替换公开的 0.4.0 便携包。
